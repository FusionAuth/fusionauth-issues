# Issue 3568: Template settings have formatting issues during tenant creation

## Verdict

**confirmed** — **Confidence: high**

The reported formatting issue was reproduced on FusionAuth 1.69.1 and remained on latest, 1.70.0. With no email or message templates configured, the Template settings section repeats both “No email templates defined” and “No message templates defined” 13 times each. Adding one email template makes email templates selectable but does not remove the repeated message-template placeholders.

## Environment

| Version | Instance status | Database | Search engine |
| --- | --- | --- | --- |
| 1.69.1 | Started for this reproduction; public image pulled successfully | PostgreSQL 16 (`postgres:16-bookworm`) | OpenSearch 2.11.0 |
| 1.70.0 (latest) | Already responding at initial check | PostgreSQL 16 (`postgres:16-bookworm`) | OpenSearch 2.11.0 |

Separate OpenSearch containers were used for each FusionAuth instance. The UI was tested in Chromium at a 2000 × 1100 viewport. No paid license was used.

## Replication steps

1. The latest instance at `http://localhost:9011` was already running. Check it with `curl -sS -H 'Authorization: $API_KEY' http://localhost:9011/api/system-configuration`.
2. Start the reported version from the repository root:

   ```sh
   REPORTED_VERSION=1.69.1 docker compose -p triage -f .github/triage/docker-compose.yml --profile reported up -d fusionauth-reported
   ```

   Wait for `curl -sS -H 'Authorization: $API_KEY' http://localhost:9012/api/status` to return a healthy response. The latest instance status endpoint reported schema version 1.70.0; the reported-version endpoint reported schema version 1.69.1.
3. On each instance, open `/admin`, sign in as `admin@example.com` with the local triage admin password `password`, and go to **Tenants** → **Add** → **Identities**.
4. Scroll to **Template settings** without creating any email or message templates. At a 2000 × 1100 viewport, the section measured 1,584 pixels wide by 809 pixels high on both versions. Observe the template placeholder text repeated down the section. Screenshots: `01-reported-1.69.1.png` and `02-latest-1.70.0.png`.
5. To check the workaround on latest, create one email template with:

   ```sh
   curl -X POST http://localhost:9011/api/email/template \
     -H "Authorization: $API_KEY" \
     -H 'Content-Type: application/json' \
     -d '{"emailTemplate":{"name":"Triage issue 3568 test","defaultSubject":"Triage","fromEmail":"triage@example.com","defaultHtmlTemplate":"<p>Triage</p>","defaultTextTemplate":"Triage"}}'
   ```

   This returned HTTP 200 with a response including `{"emailTemplate":{"id":"2d27f40c-9cd9-4c91-a267-b640582337f6","name":"Triage issue 3568 test",...}}`.
6. Reload `/admin/tenant/add`, select **Identities**, and inspect **Template settings**. The email dropdowns now list `Triage issue 3568 test`; the message-template placeholder still repeats 13 times. See `03-latest-one-email.png`.
7. Remove the temporary email template:

   ```sh
   curl -X DELETE http://localhost:9011/api/email/template/2d27f40c-9cd9-4c91-a267-b640582337f6 \
     -H "Authorization: $API_KEY"
   ```

   This returned HTTP 200.
8. The steps and screenshots can also be generated by the included script. With both instances running, set `API_KEY` to the local triage key from `.github/triage/kickstart/kickstart.json` and run:

   ```sh
   NODE_PATH="$(npm root -g)" node triage/issue-3568/repro.cjs
   ```

   The script logs the template-placeholder counts, captures all three screenshots, and deletes its temporary email template when done.

## Expected

Template settings should present a correctly formatted set of email and phone template controls, without repeated placeholder text extending down the form.

## Actual

With no templates configured, both versions displayed 13 instances each of “No email templates defined” and “No message templates defined” in the section. On latest, adding one email template populated the email-template dropdown options but left 13 “No message templates defined” placeholders. The repeated vertical content matches the reported screenshot.

The observed UI exposed the following API results for the workaround: template creation returned HTTP 200 with an `emailTemplate` object; deletion returned HTTP 200.
